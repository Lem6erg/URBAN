## Початок задачі

2. Встанови гілку й незакомічені зміни (`git status -sb`). Перевір верхні пости TODO
   та записи потрібної області. Не завантажуй усю історію без потреби.
3. Обери потрібний [маршрут задачі](task_routes.md). Відкривай відповідні фрагменти
   [карти проєкту](project_map.md) та [індексу джерел](sources.md) за потреби.
4. До зміни коду визнач Risk / Reason / Test strategy за правилами проєкту.
   Для нової функції спершу пройди шлюзи (Gate 0 → `/grill-me` → DECISIONS LOCKED → ТЗ).

## Як читати джерела

- ТЗ у `Markdown/` описує погоджений контракт; код — його реалізацію.
- TODO зберігає стан задач та історію. Handoff — знімок на дату, який потребує звірки з кодом.
- Новіша дата не доводить погодження чи заміну попереднього рішення.
- У разі суперечності звір scope і докази рішення; не перепроєктовуй мовчки.

## Підтримка

Оновлюй відповідний запис карти/індексу/маршруту, коли погоджено змінюєш шлях або контракт.
Статуси задач сюди не копіюй — вони лише в TODO. Позначай дату й обсяг перевірки;
не видавай неперевірене припущення за чинне рішення. Нові документи — посилання на наявні джерела,
без перенесення коду чи історії.
