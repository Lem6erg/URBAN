# ТЗ: KML ↔ DXF, калькулятор координат, прив'язка растру, очищення файлів (2026-11-27)

Чотири інструменти для ручних операцій між програмами. Працюють офлайн, без агентів.

## DECISIONS LOCKED

Рішення користувача (2026-11-27):
- **Р1. Растр — для Archicad.** Archicad не читає файлів прив'язки. Тому програма дає:
  - растр, повернутий північчю вгору;
  - кути й розмір у метрах для інструмента «Рисунок».
  Окремо пише world-файл (.jgw / .pgw / .tfw) — це дешево і знадобиться в ГІС.
- **Р2. Калькулятор — СК-63 також наближено (EPSG).** Позначка в назві «(наближено)» і попередження, що це для пошуку, не для документів. Якщо є ключ СК-63, він має перевагу.
- **Р3. Очищення DOCX — лише метадані.** Автор, змінив, організація, назва, тема, ключові слова, опис, шаблон, власні властивості, надбудови (webextensions). Текст, коментарі й виділення не змінюються.
- **Р4. Автор / організація — поле в програмі.** Програма пам'ятає останнє значення; порожнє поле означає стерти. Результат — копія поруч «… (чисто).docx», оригінал не змінюється. Перейменування файлів немає.

Рішення агента:
- **Р5. Спільний модуль `geo.py`:** перехід «система ↔ WGS-84». Застосовується в KML, калькуляторі й «Локації».
  - Проєкції з основою УСК-2000: ТМ → широта/довгота на Красовському → геоцентричні XYZ → WGS-84. Тобто УСК-2000 вважається геоцентричною (≈ ITRF, розбіжність з WGS-84 до ~1 м).
  - Це виправляє «Локацію»: раніше широту Красовського подавали як WGS-84, різниця до ~3 м.
  - СК-63 наближено: EPSG:7825–7827 + TOWGS84 (як у «Локації»).
  - Системи лише з ключем (напр. СК-63 за пунктами): ключ → проєкція УСК-2000 → WGS-84.
- **Р6. KML/KMZ → DXF R12.**
  - Placemark з Point, LineString, Polygon (зовнішній і внутрішні контури), MultiGeometry.
  - Шар — шлях папок KML (без папок — «KML»). Точка → POINT + TEXT з назвою.
  - Система призначення вибирається; за замовчуванням МСК-46.
  - Файл — поруч із KML «<назва> (<система>).dxf», без перезапису.
- **Р7. DXF / DWG → KML.**
  - Лінії, полілінії, точки; шар → папка KML.
  - Система визначається автоматично (як у «Локації») або вибирається вручну.
  - Далекі об'єкти (блоки в локальних координатах) відкидаються.
  - Файл — поруч «<назва>.kml».
- **Р8. Калькулятор.**
  - Вставити стовпчик точок: «[назва] X Y». X — північ, Y — схід, як у Digitals; є перемикач «E N». Роздільники: пробіл, таб, «;». Десяткова кома допустима, якщо роздільник не кома.
  - Системи: усі з `crs_keys.json`, «WGS-84 (градуси)», СК-63 наближено.
  - Точний шлях (`crs.transformer`) має перевагу, через WGS-84 — лише коли точного немає.
  - Результат можна скопіювати або зберегти TXT.
- **Р9. Прив'язка растру.**
  - Зображення відкривається в програмі (масштаб колесом, зсув правою кнопкою); точки ставляться клацанням, координати X / Y вводяться.
  - 2 точки → Гельмерт (зсув, поворот, масштаб); ≥ 3 → афінне з нев'язками.
  - Результат:
    - `<назва> (прив'язано).png` — північчю вгору, з тим самим розміром пікселя;
    - `.txt` з кутами (лівий нижній / лівий верхній), шириною й висотою в м, розміром пікселя;
    - world-файл для оригіналу.
  - Необов'язковий зсув до локального нуля (як `dmf2dxf --shift`).
- **Р10. Очищення PDF** (pypdf, BSD):
  - Author задається полем;
  - Title, Subject, Keywords, Creator, Producer стираються;
  - XMP прибирається;
  - копія «… (чисто).pdf».
