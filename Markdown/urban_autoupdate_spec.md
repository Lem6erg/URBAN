# URBAN — оновлення через GitHub Releases: ТЗ v1

Дата: 2026-11-27. Статус: DECISIONS LOCKED → реалізація. Risk: **HIGH** (запуск інсталятора, мережа, файли програми користувача).

## 1. Мета

Встановлений URBAN сам дізнається про нову версію в публічному репозиторії `Lem6erg/URBAN` і після згоди користувача ставить її поверх старої, зберігаючи налаштування.

## 3. Склад

1. `version.py` — `VERSION = '1.0.0'`, `REPO = 'Lem6erg/URBAN'`.
2. `updater.py` — без tkinter: `parse(v)`, `newer(a, b)`, `latest()` (GitHub API, таймаут 10 с, `User-Agent: URBAN-updater`) → `{version, notes, url, sha_url}`; `download(url, dst, progress)`; `sha256(path)`; `verify(path, sha_text)`; `run_installer(path)` (`/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS`, далі вихід з програми); `due(settings)` / `mark_checked(settings)`.
3. `dpt_converter.py` — `ver` з `version.py`; сторінка `p5` «Оновлення»; фонова перевірка при запуску; вікно-питання.
4. `installer/URBAN.iss` — `AppVer` з командного рядка (`/DAppVer=` з `version.py`); `CloseApplications=yes`, `RestartApplications=yes`; `[Run]` запускає URBAN і в тихому режимі (`skipifsilent` прибрати для запуску програми); транслятор і шаблон пунктів — з `installer\files\` (не з `G:\URBAN\Документація`).
5. `installer/build.ps1` — версія з `version.py`; поруч з інсталятором — `.sha256`.
6. `installer/release.ps1` — перевірки (чиста гілка, тег не існує, CHANGELOG має розділ версії) → build → `git tag vX.Y.Z` → push тегу → `gh release create` з нотатками з CHANGELOG і двома файлами.
7. `CHANGELOG.md` — розділи `## X.Y.Z — дата`.

## 4. Поведінка

- Порівняння версій — числове по компонентах (`1.0.10 > 1.0.9`); тег `vX.Y.Z`.
- Помилка мережі / API / ліміт — у журналі програми одним рядком при ручній перевірці; при автоперевірці — мовчки.
- SHA-256 не збігся → файл видалити, повідомити, нічого не запускати.
- Завантаження — у `%TEMP%\URBAN_update\`, шкала прогресу програми.
- Налаштування `%APPDATA%\URBAN` інсталятор не чіпає.
- «Пізніше» — до наступного запуску (не пропускати версію назавжди).

## 5. Перевірки (DONE)

1. Модульні перевірки `updater`: порівняння версій, розбір відповіді API (фікстура), SHA-256 збіг/незбіг.
2. Компіляція, запуск GUI в обох темах, сторінка «Оновлення».
3. Реліз `v1.0.0` на GitHub; встановлення 1.0.0 на цьому ПК (у профіль користувача, як для звичайного користувача).
4. Реліз `v1.0.1` (реальна дрібна зміна) → встановлена 1.0.0 знаходить, питає, оновлюється сама, запускається 1.0.1; тема збереглась.
5. Негатив: без мережі — мовчки; зіпсований SHA — не запускає.
