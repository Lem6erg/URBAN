# Робота з цим проєктом

URBAN — настільна програма для Windows (Python + tkinter): Archicad DXF → Digitals, DMF → DXF,
ключі систем координат, інсталятор. Це проєкт розробки програми, а не ДПТ: правила
`G:\URBAN\CLAUDE.md` і `G:\URBAN\CLAUDE\` (оформлення, норми, Кресляр) тут не діють, крім
конфіденційності (розд. «Контекст проєкту»). Мова — українська.

## Навігація по проєкту

Карта модулів, індекс джерел і маршрути читання за задачею — у
[навігації URBAN](Markdown/agentic_context/README.md). Вона доповнює ці правила;
TODO.md лишається єдиним журналом стану задач. При зміні шляху або погодженого
контракту актуалізуй відповідний запис навігації в межах тієї самої задачі.

## Економне використання контексту

- Використовуй уже надані чинні правила й прочитані незмінені фрагменти. Не перечитуй
  їх автоматично; якщо джерело могло змінитися, перевір актуальність і дочитай потрібне.
  Однаковий вміст AGENTS.md та CLAUDE.md достатньо опрацювати один раз; обидва файли зберігаються.
- Обирай маршрут задачі й читай лише потрібні розділи та модулі. Карту й індекс
  відкривай за потреби; правила безпеки лишаються чинними.
- Обмежуй виведення інструментів: спершу пошук, потім потрібний фрагмент; з довгого логу —
  підсумок і всі причини помилок. Не приховуй помилки й не скорочуй обов'язкові перевірки заради токенів.

## TODO.md оновлюється сам, без нагадувань

`TODO.md` у корені — живий стан проєкту: пости задач, новіші зверху. **Наприкінці кожної задачі**
(нова функція, виправлення, рефакторинг, нова вимога) онови `TODO.md` у тій самій відповіді,
де звітуєш про роботу. Користувач не має про це просити.

Що саме робити:

1. Новий пост для задачі: `# <назва> (<дата>; <статус>)`, нижче пункти `- [x]` / `- [ ]`.
2. Позначити зроблене: `[ ]` → `[x]`, з уточненням, якщо реалізація відрізнялася від плану.
3. Додати нові пункти: знайдені дефекти, відкладені хвости (`Поза scope: …`), дії користувача (`Користувач: …`).
4. Числа й результати перевірок — **з фактичного прогону цієї сесії**, не з пам'яті. Не було прогону — так і писати.
5. Не чистити історію: виконані пункти лишаються; ризик прибирається лише коли він справді знятий.

Якщо задача нічого в статусах не змінила — лишити файл як є і сказати про це у звіті.

## Обсяг перевірок — за ризиком задачі (агент вирішує сам)

Принцип: **перевірок рівно стільки, скільки виправдовує технічний ризик**.
Автотести: `python -m unittest discover -s tests -v` (`updater`, `pdf_raster`, `site_map`, `geo_tools`, `pz_cadastre_cz`; синтетичні дані, мережа підмінена).
Решта — ручні сценарії на копіях. Кожен підтверджений баг лишає тест на ту поведінку, що зламалась.

**Перед кодом** — три рядки в робочому плані (і потім у звіті):
`Risk: LOW / MEDIUM / HIGH` · `Reason: …` · `Test strategy: …`. Сумнів між рівнями → вищий.

| Рівень | Типово в URBAN | Перевірки |
|---|---|---|
| **LOW** | текст, підпис, іконка, тема, документація | `python -m py_compile` зміненого; запуск GUI (вікно «URBAN» відкривається) |
| **MEDIUM** | нова кнопка/вкладка з логікою; файлова логіка; DMF → DXF; підказки СК | LOW + сценарій зачепленої функції на копії в scratchpad, звірка результату (кількість об'єктів, габарит, шари) |
| **HIGH** | прив'язка `dxf_digitals.py` (ICP, поріг 95 %); перерахунок СК (`crs.py`, ключі); формат R12 для Digitals; запис/перезапис файлів користувача; інсталятор | MEDIUM + регресія на відомому випадку (тестове топо: 99,2 %, МСК-46 → УСК-2000); для інсталятора — збирання `installer\build.ps1` |

**Заборонено:** «спрощувати» перевірку, щоб отримати PASS; ховати помилки; знижувати поріг прив'язки
без рішення користувача. **Мінімальний scope:** стороннє не лагодити мимохідь — записати в `TODO.md` як `Поза scope`.

## Файли користувача й запущені програми

- Користувач може в цей момент працювати в Archicad, Digitals або встановленому URBAN.
  Не закривати й не перезапускати їх без дозволу.
- **Файли об'єктів (`G:\URBAN\<фірма>\<об'єкт>\…`) лише читати.** Тести — на копіях у scratchpad;
  проміжні файли — у TEMP; тестові результати прибирати. Програма не перезаписує наявні файли
  користувача (урок 27.11.2026: тест видалив файл користувача).
- `installer\build.ps1` перезаписує `G:\URBAN\Документація\URBAN_Setup.exe` — це його призначення;
  інші файли в `Документація\` (`URBAN.bat`, `URBAN.lnk`, транслятор, ярлики) міняти лише в задачі, що цього стосується.

## Нові функції: Gate 0 → /grill-me → DECISIONS LOCKED → ТЗ → реалізація

- Для нової функції або архітектурного рішення (новий формат, нова СК, зміна алгоритму прив'язки):
  Gate 0 (дослідження коду й даних лише читанням) → `/grill-me` → `DECISIONS LOCKED` →
  ТЗ у `Markdown/urban_<тема>_spec.md` → реалізація → перевірки → коміт.
- Під час grill код не міняти; користувача питати лише про рішення, яких з коду й даних не вивести.
- Дрібний фікс, текст чи вигляд — без grill.
- Зафіксоване рішення виявилось хибним — зупинитись і повідомити, тихо не перепроєктовувати.

## Контекст проєкту

- Передача з ДПТ-сесії (факти про Archicad, Digitals, DMF, СК, помилки) — [Markdown/urban_handoff_2026-11-27.md](Markdown/urban_handoff_2026-11-27.md).
- **Конфіденційність:** матеріали замовників (DMF, DXF об'єктів, власники з DMF, адреси) не надсилати
  стороннім сервісам і не переносити в код, коміти, TODO й повідомлення.
- **Репозиторій публічний** (`github.com/Lem6erg/URBAN`, рішення користувача 27.11.2026: з нього програма
  бере оновлення). Усе, що комітиться, бачить будь-хто: жодних назв об'єктів і фірм, адрес, к.н., координат,
  зсувів конкретних експортів, імен людей, шляхів до папок об'єктів. Тестові дані — лише синтетичні.
  Перед кожним комітом — пошук цих слів у diff (`git diff --cached`). Дані об'єктів у git не потрапляють (`.gitignore`).
- **Git:** коміт — наприкінці задачі; push — лише за командою користувача.
- **Версії й випуск** ([ТЗ](Markdown/urban_autoupdate_spec.md)): версія лише в `version.py`; перед випуском — підняти її,
  дописати `## X.Y.Z — дата` у `CHANGELOG.md`, закомітити, далі `installer\release.ps1` (тести → збирання → тег →
  GitHub Release). Випуск — лише за командою користувача: його одразу отримують усі встановлені програми.
- `dmf2dxf.py` спільний із Кресляром ДПТ (база `G:\URBAN\CLAUDE\07`, `08`, `09`): інтерфейс командного рядка
  `dmf2dxf.py in.dmf out.dxf [--shift X Y]` не ламати.
- PowerShell: шлях з `[app]` — через `-LiteralPath`. Файли з кирилицею для PowerShell 5.1 та Inno Setup — UTF-8 з BOM.
